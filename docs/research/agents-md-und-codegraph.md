# Schlanke AGENTS.md lenkt Agents zum Graphen

Für sidekick ist die beste Lösung eine **kurze, handgeschriebene AGENTS.md (etwa 50–100 Zeilen) als einzige gemeinsame Quelle**. Daneben braucht es eine echte `CLAUDE.md`, die nur `@AGENTS.md` und wenige Claude-spezifische Ergänzungen enthält. Die CodeGraph-Regel gehört als kurzer, bedingter Block in die AGENTS.md und nicht als Skill daneben. Begründet ist das durch drei Befunde. Erstens bringen Kontextdateien laut rigoroser Studien keinen verlässlichen Erfolgsgewinn, erhöhen die Kosten aber um rund 20 %. Nützlich sind sie nur für nicht offensichtliche Konventionen, Befehle und Grenzen. Zweitens folgen Agents Werkzeughinweisen in solchen Dateien zuverlässig. Drittens benutzen Subagents CodeGraph ohne einen solchen Block fast nie, weil sie die MCP-Anweisungen gar nicht erhalten. CodeGraph lohnt sich bei Fragen zu Abläufen, Architektur und „wer ruft das auf / was bricht“. Für exakte Strings, vollständige Umbenennungen, Konfiguration und Markdown bleibt grep/Read das richtige Werkzeug. Die Gewinne wachsen mit der Größe der Codebasis und mit dem Suchaufwand, den eine Frage verursacht. Im heutigen sidekick-Repo ist der Index leer (0 Dateien, 0 Knoten). Weil `.codegraph/.gitignore` eingecheckt ist, existiert das Verzeichnis trotzdem in jedem Klon. Damit greift die Standardbedingung des Installers („wenn `.codegraph/` existiert, nutze es“) ins Leere. Die AGENTS.md muss deshalb auf einen *nicht leeren* Index prüfen. Code-Navigations-Skills und ein SessionStart-Hook lohnen sich erst, wenn mit Phase 1 echter TypeScript-Code entsteht.

## AGENTS.md ist Standard, Claude Code liest sie aber nur ohne CLAUDE.md

AGENTS.md ist ein reines Markdown-Format ohne Pflichtfelder, ein „README for agents“, das nach Angaben der Betreiber in über 60.000 Open-Source-Projekten genutzt wird ([agents.md](https://agents.md/)). OpenAI hat das Format im August 2025 veröffentlicht. Am 9. Dezember 2025 ging es zusammen mit Anthropics MCP und Blocks goose als Gründungsprojekt an die **Agentic AI Foundation (AAIF) unter dem Dach der Linux Foundation** ([OpenAI](https://openai.com/index/agentic-ai-foundation/); [Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)). Codex, der Copilot Coding Agent, Cursor, Zed, Jules, Amp, Windsurf und rund 20 weitere Werkzeuge lesen die Datei nativ ([agents.md](https://agents.md/)). Codex fügt alle AGENTS.md vom Git-Root bis zum Arbeitsverzeichnis zusammen, wobei die nähere Datei gewinnt. Die Obergrenze liegt standardmäßig bei **32 KiB**, und `@`-Importe interpretiert Codex nicht ([OpenAI Codex Docs](https://developers.openai.com/codex/guides/agents-md)). Ein Vorschlag für Version 1.1 mit Frontmatter (`description`, `tags`) wurde geschlossen ([Issue #135](https://github.com/agentsmd/agents.md/issues/135)). Frontmatter in AGENTS.md sollte man deshalb nicht einsetzen.

Claude Code liest AGENTS.md seit v2.1.277 nativ, allerdings nur, **wenn weder CLAUDE.md noch CLAUDE.local.md im Pfad liegt**. Gibt es beide Dateien, lädt Claude Code ausschließlich CLAUDE.md. Enthält CLAUDE.md die Zeile `@AGENTS.md`, werden beide geladen, AGENTS.md genau einmal ([Claude Code Docs: Memory](https://code.claude.com/docs/en/memory)). Daraus folgt eine leicht übersehene Falle: Legt jemand eine persönliche `CLAUDE.local.md` an, schaltet er damit stillschweigend die AGENTS.md des Teams ab ([wmedia.es](https://wmedia.es/en/tips/claude-code-agents-md-import-symlink)). Anthropic empfiehlt deshalb als Brücke eine CLAUDE.md mit `@AGENTS.md` und einem Abschnitt `## Claude Code`. Ein Symlink ist schlechter, weil Edit/Write nicht durch Symlinks schreiben und Windows sie als einzeilige Textdatei auscheckt. Ein Prosa-Hinweis wie „lies AGENTS.md“ ist unzuverlässig ([Claude Code Docs: Memory](https://code.claude.com/docs/en/memory)). Für sidekick ist der wichtigste Präzedenzfall Next.js: Ab Version 16.2 erzeugt `create-next-app` **eine AGENTS.md mit verwaltetem Block plus eine CLAUDE.md mit `@AGENTS.md`** ([Next.js 16.2 AI blog](https://nextjs.org/blog/next-16-2-ai)). Der Block zwischen `<!-- BEGIN:nextjs-agent-rules -->` und `<!-- END:nextjs-agent-rules -->` verweist auf versionsgenaue Dokumentation in `node_modules/next/dist/docs/` und wird von `next dev` wieder eingefügt. Eigene Regeln gehören außerhalb der Marker ([Next.js agentRules](https://nextjs.org/docs/app/api-reference/config/next-config-js/agentRules)). Die hier vorgeschlagene Struktur deckt sich also mit dem, was der geplante Stack ohnehin erzeugt. Ältere Quellen, nach denen Claude Code AGENTS.md ignoriert, sind überholt ([augmentedswe](https://www.augmentedswe.com/p/symlink-claudemd-agentsmd) widerspricht den offiziellen Docs).

## Weniger Text bringt mehr: Studien raten zu Befehlen, Fallstricken und Grenzen

Die beste verfügbare Evidenz spricht gegen ausführliche Dateien. Die ETH-Zürich-Studie „Evaluating AGENTS.md“ (ICLR 2026, MemAgents-Workshop) findet, dass Kontextdateien **die Erfolgsquote im Allgemeinen nicht verbessern, die Inferenzkosten aber im Schnitt um über 20 % erhöhen**. Von LLMs generierte Dateien senkten den Erfolg leicht, um −0,5 % bzw. −2 % (nicht signifikant). Von Entwicklern geschriebene Dateien brachten durchschnittlich +2,4 % (p = 21 %) und waren signifikant besser als generierte ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988); [HTML v3](https://arxiv.org/html/2602.11988v3)). Repository-Übersichten halfen nicht. Nützlich waren die Dateien dort, wo sie nicht standardmäßige Praktiken festhielten. Die Autoren raten, nur minimale Anforderungen zu beschreiben ([SRI Lab](https://www.sri.inf.ethz.ch/publications/gloaguen2026agentsmd)). Lulla et al. messen dagegen **28,6 % weniger Laufzeit und 16,6 % weniger Output-Tokens** bei vergleichbarem Ergebnis ([arXiv 2601.20404](https://arxiv.org/abs/2601.20404v2)). Eine kleine Ablation mit Claude Code und Codex sieht keinen messbaren Effekt auf die Korrektheit und erklärt den Widerspruch mit unterschiedlicher Aufgabenwahl ([arXiv 2607.27250](https://arxiv.org/abs/2607.27250v1)). Die Befunde widersprechen sich also im Detail, zeigen aber in dieselbe Richtung: Eine knappe, handgeschriebene Datei schadet nicht und spart unter Umständen Schritte. Eine lange oder generierte Datei kostet nur.

Anthropic kommt praktisch zum selben Schluss. CLAUDE.md-Dateien sollen **unter 200 Zeilen** bleiben, und Importe ordnen den Inhalt zwar, senken aber nicht die Kontextkosten ([Memory](https://code.claude.com/docs/en/memory)). Architektur- und Dateibaum-Beschreibungen führt Anthropic ausdrücklich als überholten Rat. Der Test lautet: „Could it find this by reading the code? Would it actually go and look? If both are yes, leave it out.“ Hineingehören die genauen Befehle zum Testen, Typprüfen und Linten (inklusive Einzeltest), irreführende Stellen im Code, Entscheidungen, die nicht im Repo stehen, und alles, „you've had to correct twice already“ ([Best practices](https://code.claude.com/docs/en/best-practices)). GitHubs Auswertung von über 2.500 Dateien ergänzt: Befehle mit Flags früh nennen, den Stack mit Versionen angeben und Grenzen dreistufig formulieren (immer, erst fragen, nie). „Never commit secrets“ war die häufigste hilfreiche Regel ([GitHub Blog](https://github.blog/ai-and-ml/github-copilot/how-to-write-a-great-agents-md-lessons-from-over-2500-repositories)). Zum Tonfall rät Anthropic von Großbuchstaben und IMPORTANT ab, weil aktuelle Modelle dann die Regel übertreiben. Was jedes Mal passieren muss, gehört in einen Hook, eine Deny-Regel oder die CI ([Best practices](https://code.claude.com/docs/en/best-practices)). Eine Regel wirkt besser, wenn sie ihren Grund nennt ([Claude prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/claude-prompting-best-practices)).

Für Werkzeugregeln ist der Effekt dagegen gut belegt. In der ETH-Studie wurde `uv` 1,6-mal pro Aufgabe genutzt, wenn die Datei es erwähnte, und unter 0,01-mal ohne Erwähnung. Repo-spezifische Werkzeuge stiegen von unter 0,05 auf 2,5 Aufrufe ([arXiv HTML v3](https://arxiv.org/html/2602.11988v3)). Eine CodeGraph-Regel in der AGENTS.md wird also befolgt. Das wirkt in beide Richtungen: Eine falsch gesetzte Regel erzeugt genauso zuverlässig nutzlose Aufrufe. Anthropic warnt deshalb vor pauschalen Vorgaben wie „Default to using [tool]“ und „If in doubt, use [tool]“, weil sie zu übermäßigem Auslösen führen. Besser ist eine gezielte Bedingung mit Begründung ([Claude prompting best practices](https://docs.claude.com/en/docs/build-with-claude/prompt-engineering/claude-prompting-best-practices)). Eine Gegenstimme kommt von Vercel. Dort schnitt ein ständig präsenter Verweis in der AGENTS.md mit **100 % gegenüber höchstens 79 %** besser ab als Skills, die bei Bedarf laden, weil Agents oft nicht erkennen, *wann* sie nachschlagen sollten ([Next.js 16.2 AI blog](https://nextjs.org/blog/next-16-2-ai); Herstellerstudie). Für eine Regel, die *vor* der Suche greifen soll, ist das ein starkes Argument, sie in die immer geladene Datei zu schreiben.

## CodeGraph gewinnt bei Abläufen und Wirkungsradius, grep bei Strings und Umbenennungen

CodeGraph v1.6.2 indexiert Code lokal mit tree-sitter in eine SQLite/FTS5-Datenbank unter `.codegraph/codegraph.db`. Standardmäßig stellt es **ein einziges MCP-Tool bereit, `codegraph_explore`**. Es liefert wörtlichen, zeilennummerierten Quelltext im Read-Format plus Aufrufpfade, auch über dynamische Dispatch-Grenzen wie Callbacks oder JSX-Kinder hinweg, und eine Zusammenfassung des Wirkungsradius ([GitHub colbymchenry/codegraph](https://github.com/colbymchenry/codegraph); [Docs: MCP Server](https://colbymchenry.github.io/codegraph/reference/mcp-server)). Die CLI bildet das ab: `codegraph explore` liefert dieselbe Ausgabe, dazu kommen `node`, `callers`, `callees`, `impact --depth N`, `affected --stdin` (betroffene Tests über transitive Importe), `status`, `sync -q` und `unlock` (lokal per `codegraph --help` geprüft). Ein Watcher im MCP-Server synchronisiert mit 2 s Entprellung. Hinzu kommen ein Banner je Datei, das veraltete Einträge markiert, und ein Abgleich beim Verbindungsaufbau, der auch `git pull` und Änderungen zwischen Sessions erfasst ([Docs: Indexing](https://colbymchenry.github.io/codegraph/guides/indexing/)). Für Claude Code ist **`"alwaysLoad": true`** im MCP-Eintrag entscheidend, denn sonst landet das Tool hinter der Tool-Suche ([Claude Code MCP docs](https://code.claude.com/docs/en/mcp)).

Die Empfehlungen des Autors stehen in den MCP-Initialisierungsanweisungen. `codegraph_explore` soll *vor* Read/Grep aufgerufen werden, und zwar nicht nur bei Fragen, sondern auch vor und während Änderungen, damit der Agent den Wirkungsradius kennt, bevor er editiert. Die Ergebnisse soll er nicht per grep nachprüfen, und die Suche soll er nicht an Subagents abgeben, die Dateien lesen. grep/Read bleiben für Konfiguration, Dokumentation, nicht abgedeckte Details und als veraltet markierte Dateien. In nicht indexierten Projekten soll der Agent CodeGraph für den Rest der Session meiden und **`codegraph init` nie selbst ausführen**, denn Indexieren entscheidet der Nutzer (lokal: `server-instructions.js` im installierten Paket, gespiegelt im [GitHub-README](https://github.com/colbymchenry/codegraph)). `codegraph install` schreibt deshalb zusätzlich einen kurzen, durch Marker begrenzten Block in CLAUDE.md, AGENTS.md oder GEMINI.md. Der Grund ist für sidekick als künftiger Agent-Hub mit delegierender Arbeitsweise zentral: **Task-Subagents bekommen die Instruktionsdatei, aber nicht die MCP-Anweisungen**. In einer Messung nutzten Subagents CodeGraph ohne den Block in etwa 1 von 9 Läufen und mit dem Block durchgängig (lokal: `instructions-template.js`). Der Block ist bewusst kurz gehalten. Ein früheres ausführliches Playbook hat der Autor wegen der Tokenkosten wieder entfernt.

Bei der Wirksamkeit ist Vorsicht angebracht. Der Hersteller-Benchmark (7 Repos, Opus 4.8, je eine Architekturfrage) meldet **88 % weniger Tool-Aufrufe, 62 % weniger Tokens und 44 % geringere Kosten**. Die Spanne reicht von 71–78 % Ersparnis bei VS Code und Excalidraw bis zu einem Gleichstand bei Gin mit rund 110 Dateien ([GitHub-README](https://github.com/colbymchenry/codegraph)). Derselbe Hersteller misst aber auch, dass am Sessionende **rund 80 % mehr Abrufkontext im Fenster verbleibt** (VS Code: 67k gegenüber 18k Tokens). Im Sonnet-Mehrrundenszenario wurde Django mit CodeGraph sogar 17 % teurer ([Residual-Context-Benchmark](https://github.com/colbymchenry/codegraph/blob/main/docs/benchmarks/residual-context-occupancy.md)). Einen unabhängigen Benchmark speziell für CodeGraph gibt es nicht. Anthropic hat sich für Claude Code bewusst gegen einen Index und für agentische Suche entschieden ([Boris Cherny auf X](https://x.com/bcherny/status/2017824286489383315); [Claude Code FAQ](https://support.claude.com/en/articles/12386420-claude-code-faq)). Für große Codebasen empfiehlt Anthropic inzwischen trotzdem symbolbasierte Suche, weil grep auf einen häufigen Funktionsnamen „thousands of matches“ liefert ([Anthropic: large codebases](https://claude.com/blog/how-claude-code-works-in-large-codebases-best-practices-and-where-to-start)). Eine unabhängige LSP-vs-grep-Pilotstudie zeigt, wo die Grenze verläuft. Semantische Werkzeuge bringen Präzision bei der Referenzsuche (1,00 gegenüber 0,76) und helfen in lexikalisch verrauschtem Code. Bei der reinen Lokalisierung kosten sie mehr Tokens. **Mehrdatei-Umbenennungen löst grep zu 100 %, LSP nur zu 67–83 %**, weil semantische Referenzen Kommentare und Strings auslassen ([lsp-vs-grep-token-study](https://github.com/agentconnect-md/lsp-vs-grep-token-study/blob/main/README.md); kleine Stichprobe). Graph-Ansätze in der Forschung wie RepoGraph (+32,8 % relativ auf SWE-bench-Lite) stützen den Nutzen strukturierter Navigation grundsätzlich ([arXiv 2410.14684](https://arxiv.org/html/2410.14684v1)).

Daraus ergibt sich eine klare Arbeitsteilung, die so in die AGENTS.md gehört:

| Situation | Werkzeug | Grund |
|---|---|---|
| „Wie funktioniert X“, Ablauf X→Y, Architektur, Bug-Lokalisierung im Code | `codegraph_explore` bzw. `codegraph explore "<Namen>"` | Ein Aufruf statt einer grep/Read-Schleife; Aufrufpfade über dynamischen Dispatch |
| Vor dem Ändern eines benannten Symbols | explore mit dem Symbolnamen, bei Bedarf `codegraph impact` | Quelltext plus Aufrufer plus Wirkungsradius in einem Aufruf |
| Welche Tests betroffen sind | `git diff --name-only HEAD \| codegraph affected --stdin --quiet` | Gezielter Testlauf statt der vollen Suite |
| Exakte Strings, vollständige Umbenennung oder Löschung | grep (zusätzlich) | Der Graph enthält keine Kommentare, Strings und Doku |
| Markdown, JSON/YAML, Konfiguration, `docs/` | grep/Read | Wird nicht indexiert |
| Banner meldet veraltete Dateien, Index leer oder fehlend | Read bzw. grep | Der Index ist dort nicht verlässlich |
| Korrektheit | `tsc`, Tests, Linter | CodeGraph validiert nichts |

Für sidekick ist ein lokal geprüftes Detail besonders wichtig. `codegraph status` meldet **Files: 0, Nodes: 0, Edges: 0**, und `codegraph explore` antwortet „This project has nothing indexed“. Da `.codegraph/.gitignore` laut `git ls-files` eingecheckt ist, existiert `.codegraph/` in jedem frischen Klon, auch ganz ohne Datenbank. Die Bedingung des Installer-Blocks („a `.codegraph/` directory exists“) ist also **in sidekick immer erfüllt, auch wenn der Index leer ist oder fehlt**. Die eigene Regel sollte deshalb auf einen nicht leeren Index abstellen und eine leere Antwort als Signal zum Wechsel auf grep/Read behandeln. Außerdem ist der globale Nutzer-Block in `~/.claude/CLAUDE.md` bereits vorhanden. Für Claude Code beim Repo-Eigentümer wäre der Repo-Block also teilweise doppelt. Das ist hinnehmbar, denn Codex, andere Teammitglieder und Cloud-Sessions ohne diese persönliche Datei brauchen ihn.

## Skills tragen Abläufe, keine Immer-Regeln

Ein Agent Skill ist ein Ordner mit `SKILL.md` (YAML-Frontmatter mit `name` und `description`, dann Markdown) und optionalen Ordnern `scripts/`, `references/` und `assets/`. Das Format ist ein offener Standard ([agentskills.io](https://agentskills.io/specification)), den Anthropic am 22. Oktober 2026 ebenfalls an die AAIF übergeben hat ([Anthropic](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)). Beim Start lädt nur die Metadatenebene mit etwa 100 Tokens. Der Rumpf (empfohlen unter 5.000 Tokens bzw. 500 Zeilen) lädt erst bei Aktivierung, Ressourcen nur bei Bedarf. `name` muss dem Ordnernamen entsprechen ([agentskills.io](https://agentskills.io/specification)). Claude Code liest `.claude/skills/<name>/SKILL.md` und erweitert den Standard um Felder wie `paths`, `disable-model-invocation` und `context: fork`. Beschreibung und `when_to_use` werden zusammen bei 1.536 Zeichen abgeschnitten ([Claude Code Skills](https://code.claude.com/docs/en/skills)). Codex liest `.agents/skills` ([Codex Skills](https://developers.openai.com/codex/skills)). Cursor liest zusätzlich `.claude/skills` ([Cursor](https://cursor.com/docs/skills)), Copilot liest `.github/skills`, `.claude/skills` und `.agents/skills` ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills)). Wer portabel bleiben will, beschränkt das Frontmatter auf die Standardfelder.

Für die Aufgabenteilung formuliert Anthropic Heuristiken. Wird eine Konvention zweimal falsch umgesetzt, gehört sie in CLAUDE.md. Wird dasselbe Playbook zum dritten Mal eingefügt, wird es ein Skill. Was jedes Mal passieren muss, wird ein Hook. Das Muster „Skill + MCP“ beschreibt Anthropic so: MCP stellt die Verbindung her, der Skill lehrt den guten Gebrauch ([Features overview](https://code.claude.com/docs/en/features-overview)). Daraus folgt das wichtigste Negativergebnis: **Ein Skill „codegraph_explore vor dem Editieren“ wäre falsch platziert**. Ein Skill lädt erst, wenn der Agent ihn für relevant hält, und genau diesem Moment soll die Regel vorausgehen. Diese Aufgabe erfüllt bereits die immer geladene Ebene aus MCP-Anweisungen und AGENTS.md-Block. Ebenso falsch wäre ein Skill mit `context: fork` und `agent: Explore`. Der eingebaute Explore-Agent startet ohne CLAUDE.md ([Claude Code Skills](https://code.claude.com/docs/en/skills)), verlöre also den CodeGraph-Block, und das widerspricht CodeGraphs Warnung vor delegierter Erkundung.

Sinnvoll sind dünne Hüllen um die CLI-Verben, die der MCP-Standard nicht listet. CodeGraph selbst liefert keinen nutzerseitigen Skill. Community-Skills zur Impact-Analyse arbeiten meist mit grep oder einem zweiten Indexer ([biyer/impact-analyzer](https://github.com/biyer/impact-analyzer); [Understand-Anything](https://github.com/Egonex-AI/Understand-Anything)). Sie eignen sich als Vorlage für Formulierungen, nicht als Abhängigkeit. Vier Kandidaten bieten sich an. `analyzing-change-impact` läuft vor Umbenennung, Refactoring oder Signaturänderung und nutzt explore, `impact`, `callers` und `affected`, um einen kurzen Risikobericht zu erstellen. `selecting-affected-tests` läuft nach Änderungen über `codegraph affected` und braucht wenig Spielraum, idealerweise mit gebündeltem Skript. `troubleshooting-codegraph` dient als Nachschlagewerk für veraltete Ergebnisse, Writer-Locks, „Transport closed“ und WSL-Probleme. `touring-the-codebase` ist eine nur vom Nutzer aufrufbare Einführungstour. Die Beschreibung sollte mit dem Hauptanwendungsfall beginnen und Formulierungen enthalten, die Nutzer wirklich tippen, etwa „what calls X“, „was bricht, wenn…“ oder „sicher umbenennen“. Getestet wird nach dem Prinzip „evaluations first“: drei oder mehr Prompts je Skill, ausgeführt in frischen Sessions mit und ohne Skill, verglichen nach Tool-Aufrufen, Reads und Korrektheit ([Anthropic Best Practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Keiner dieser Kandidaten hat in sidekick heute etwas zu tun, denn ohne Quellcode gibt es weder Wirkungsradius noch Tests.

## Empfehlung für netzkontrast/sidekick

**AGENTS.md jetzt anlegen, auf Deutsch, handgeschrieben, Ziel 50–80 Zeilen, später höchstens 120.** Der folgende Gliederungsvorschlag enthält nur, was ein Agent nicht selbst aus dem Repo erschließt. Die Vision, die Kernbegriffe und den Repo-Baum aus der README wiederholt er bewusst nicht.

```markdown
# AGENTS.md – sidekick (Agent Hub)

## Projektstand
Phase 0a/0b: Das Repo enthält nur Markdown (Vision, Analyse). Spec-driven:
Verhaltensänderungen beginnen in der Spec (docs/), erst danach folgt Code.
Sprache der Doku: Deutsch. Maßgeblich: docs/vision.md, docs/analyse-und-uebernahmeplan.md.

## Befehle
(heute keine; ab Phase 1 genau hier: pnpm install / dev / build,
Einzeltest, typecheck `pnpm tsc --noEmit`, lint – mit Flags)

## Konventionen, die nicht offensichtlich sind
- research_notes/ und reports/ sind gitignored; fertige Berichte gehören nach docs/research/.
- Offene Entscheidungen nicht stillschweigend festlegen, sondern in docs/vision.md §26 eintragen.
- (später: Drizzle-Migrationen, Outbox-Muster, Effekte nur über den Hub – mit einem Satz Begründung)

## Code-Navigation (CodeGraph)
Wenn das Repo indexiert ist (`codegraph status` zeigt Files > 0), nutze CodeGraph
VOR grep/Read, um Code zu verstehen oder zu finden, auch vor Änderungen:
- MCP-Tool (falls verfügbar): `codegraph_explore` mit Symbolnamen oder Frage.
  Ist es nur verzögert gelistet, lade es per Tool-Suche.
- Shell (funktioniert immer): `codegraph explore "<Symbole oder Frage>"`;
  vor Änderungen `codegraph impact <Symbol>`, danach
  `git diff --name-only HEAD | codegraph affected --stdin --quiet`.
Grund: Der vorgebaute Index liefert Quelltext, Aufrufer und Wirkungsradius in einem Aufruf.
grep/Read bleiben richtig für: Markdown/Doku/Konfiguration, exakte Strings,
vollständige Umbenennungen (Kommentare/Strings), Dateien mit Staleness-Banner,
und wenn explore „nothing indexed“ meldet. Ergebnisse nicht per grep nachprüfen.
`codegraph init` nicht selbst ausführen; Indexieren entscheidet der Mensch.
In langen Sessions gezielt nach Symbolnamen fragen statt breit wiederholt.

## Grenzen
- Immer: Änderungen über Branch/PR.
- Erst fragen: neue Abhängigkeiten, Änderungen an der Spec-Struktur, Löschen von Doku.
- Nie: Secrets oder .env committen; Effekte (Push, Merge, Veröffentlichung) ohne Auftrag.

## Git/PR
(Commit-Stil, PR-Beschreibung, Review-Regeln; optional `## Code Review Rules` für Codex)
```

**CLAUDE.md mit `@AGENTS.md`: ja, jetzt.** Claude Code würde eine AGENTS.md zwar auch allein lesen. Eine einzige `CLAUDE.local.md` oder eine ältere Version als v2.1.277 schaltet sie aber ab, und `create-next-app` legt später ohnehin genau dieses Paar an. Die Datei besteht aus `@AGENTS.md` und einem kurzen Abschnitt `## Claude Code`. Dort steht der Hinweis, dass der MCP-Eintrag für CodeGraph `alwaysLoad: true` tragen sollte, damit `codegraph_explore` nicht hinter der Tool-Suche verschwindet. Außerdem gehört dort die Regel hin, Code-Erkundung nicht an Explore-Subagents abzugeben, sondern direkt zu fragen. Falls `codegraph install` später seinen eigenen Block mit den Markern `<!-- CODEGRAPH_START -->`/`<!-- CODEGRAPH_END -->` einfügt, sollte man ihn mit dem obigen Abschnitt zusammenführen und nicht doppelt stehen lassen. Wenn Next.js eingerichtet wird, bleibt dessen verwalteter Block erhalten, und die eigenen Regeln stehen außerhalb der Marker. Harte Regeln wie das Verbot, `.env` zu lesen oder zu committen, gehören als Deny-Regel in `.claude/settings.json` und nicht in Großbuchstaben in die Datei.

**Skills: jetzt keine CodeGraph-Skills.** Sie hätten im reinen Markdown-Repo nichts zu tun, und ungetestete Skill-Beschreibungen kosten bei jeder Anfrage Kontext. Sobald der erste TypeScript-Code und ein Test-Runner da sind (Phase 1), kommen `analyzing-change-impact` und `selecting-affected-tests` in `.claude/skills/`. Das Frontmatter beschränkt sich auf `name`, `description` und `allowed-tools` mit den reinen Lese-Befehlen, damit Codex, Copilot und Cursor die Skills ebenfalls lesen können. Ob zusätzlich `.agents/skills` als Spiegel nötig ist, sollte man pro Tool prüfen. `troubleshooting-codegraph` lohnt sich erst nach Anthropics Drei-Mal-Regel, also wenn Index-Probleme wiederholt auftreten. `touring-the-codebase` kommt erst, wenn die Codebasis so groß ist, dass neue Mitwirkende eine Tour brauchen. Jeder Skill startet mit drei Eval-Prompts und einem Vergleich mit und ohne Skill. Für den Agent-Hub selbst sind ohnehin die Playbook-Skills interessanter, etwa der Spec-Review nach den Entscheidungstoren A–D. Sie liegen aber außerhalb dieser Frage.

**SessionStart-Hook: jetzt nicht, später gezielt für Cloud-Sessions.** Lokal ist er unnötig, weil Watcher und Abgleich beim Verbindungsaufbau die Aktualität sichern. Ein synchroner Sync beim Start kostet Latenz, und bei einem Timeout verwirft Claude Code die Ausgabe ([Hooks reference](https://code.claude.com/docs/en/hooks)). Heute würde der Hook einen leeren Index synchronisieren. Sinnvoll wird er, sobald Code existiert, und zwar in kurzlebigen Cloud-Containern wie Claude Code Remote oder Codex Cloud. Dort startet jede Session mit einem frischen Klon, in dem `.codegraph/` nur die `.gitignore` enthält, und reine CLI-Agents lösen nie einen Abgleich aus. Dann empfiehlt sich ein auf `startup` beschränkter, abgesicherter Hook mit `async: true`, etwa `command -v codegraph >/dev/null && { [ -f .codegraph/codegraph.db ] && codegraph sync --quiet || codegraph init -y; }`. Weil er eingecheckt wird, ist das Indexieren dann eine bewusste Entscheidung des Menschen. Ob ein solcher Sync mit einem gleichzeitig laufenden Daemon um den Writer-Lock konkurriert, ist nicht geprüft und muss vor dem Einsatz getestet werden. Für lokale Setups mit abgeschaltetem Watcher (WSL `/mnt/*`, `CODEGRAPH_NO_DAEMON=1`) sind CodeGraphs eigene Git-Hooks die bessere Wahl. Sie laufen im Hintergrund nach Commit, Merge und Checkout.

## Conclusion

Der eigentliche Hebel ist nicht, wie viel Text eine AGENTS.md enthält, sondern dass Werkzeughinweise darin verlässlich befolgt werden. Das macht die CodeGraph-Regel zugleich wirksam und riskant. Richtig formuliert lenkt sie Hauptagent und Subagents bei Ablauf- und Wirkungsfragen auf einen einzigen Aufruf. Zu pauschal formuliert, oder an ein Verzeichnis gekoppelt, das in sidekick immer existiert, führt sie zu leeren Abfragen, Mehrkosten und im schlimmsten Fall zu unvollständigen Umbenennungen. Die Bedingung „Index nicht leer“ und die ausdrückliche grep-Ausnahme sind deshalb wichtiger als jede Hervorhebung.

Für einen Agent Hub, der künftig selbst Aufträge an Coding-Agents verteilt, ergibt sich daraus noch eine Folgerung über das eigene Repo hinaus. Die in diesem Bericht beschriebene Schichtung (immer geladene Regeln in AGENTS.md, Abläufe in Skills, Erzwungenes in Hooks und CI) ist im Kleinen genau das Modell aus „Deterministisch steuern, intelligent arbeiten“. Es lohnt sich, sie hier sauber vorzuleben und später mit den Scorecards des Hubs zu messen, etwa als Anteil der Runs, die vor dem ersten Edit den Graphen befragt haben. Bislang fehlen unabhängige Benchmarks für CodeGraph. Eigene Messungen im Hub wären deshalb belastbarer als jede Herstellerzahl.
