**Kurz gesagt:** Ob libx taugt, hängt an einer Frage, die nur du bzw. der Owner beantworten kann. Müssen Aufgaben nach einem Absturz **genau einmal** laufen, ist libx ungeeignet. Reicht **mindestens einmal**, kommt es in Frage, aber nur unter Bedingungen. Die offene Frage steht auch in `auftrag.md:4-5`.

**Was ich geprüft habe:** Ich habe nur den Code gelesen, nichts ausgeführt. Tests gibt es keine. Im Verzeichnis liegen nur `README.md` und `jobs.py`, und `jobs.py` enthält nur die Funktion `resume` (3 Zeilen).

**Was der Code tut** (`vendor/libx/jobs.py:1-3`): Beim Neustart werden alle Aufgaben mit Status `running` wieder auf `queued` gesetzt.

**Was daraus folgt:**

1. **Garantie: mindestens einmal, nicht genau einmal.** Stürzt das Programm ab, während eine Aufgabe läuft, kann sie schon teilweise oder ganz erledigt sein. Trotzdem wird sie noch einmal ausgeführt. Ein Export entstünde dann doppelt, eine Erinnerung ginge zweimal raus. Eine Absicherung gegen solche Doppelungen gibt es nicht, auch keine Kennung, die eine wiederholte Ausführung erkennt.
2. **Es wird nicht geprüft, ob eine Aufgabe wirklich abgebrochen ist.** `resume` setzt *jede* laufende Aufgabe zurück. Es gibt keine Zeitgrenze und kein Lebenszeichen der arbeitenden Prozesse. Laufen mehrere Prozesse und einer startet neu, bekommen Aufgaben, die noch ordentlich laufen, wieder `queued` und werden doppelt ausgeführt.
3. **Kein Schutz bei gleichzeitigem Zugriff.** Das Zurücksetzen läuft Zeile für Zeile, ohne sichtbare Transaktion und ohne Sperre.
4. **README und Code passen nicht genau zusammen.** Laut README startet libx die Aufgaben neu, der Code setzt sie aber nur auf `queued`. Wer sie danach abholt, steht nicht im vorliegenden Code.
5. **Vieles lässt sich nicht beurteilen**, weil es im Verzeichnis fehlt: wie Aufgaben eingereiht und abgeholt werden, Wiederholungsversuche, Umgang mit Fehlern. Die Lizenz (MIT) ist unproblematisch.

**Meine Empfehlung:**
- **Genau einmal nötig:** libx nicht verwenden, oder die Aufgaben selbst gegen Doppelausführung absichern (z. B. eine eindeutige Kennung pro Export bzw. Erinnerung und ein Vermerk „schon gesendet“). Dann reicht „mindestens einmal“ wieder aus.
- **Mindestens einmal reicht:** libx ist möglich, wenn nur *ein* Prozess die Aufgaben abarbeitet oder `resume` nur bei einem Kaltstart aufgerufen wird. Vor einer endgültigen Entscheidung sollte man außerdem den vollständigen Code mit dem Einreihen und Abholen von Aufgaben ansehen.

Doppelte Erinnerungen dürften für Nutzer am ärgerlichsten sein. Wenn ihr libx nehmt, würde ich daher dort zuerst eine Absicherung gegen Doppelungen einbauen.
