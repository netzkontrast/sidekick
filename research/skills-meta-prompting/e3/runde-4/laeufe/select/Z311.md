# Recherchebericht: kvstash als Sitzungscache für den Ticket-Dienst

**Kurzantwort:** Nein. kvstash in Version 0.4.1 erfüllt keine der beiden Anforderungen so, wie das README es verspricht. Laut Code wird die Ablaufzeit in Millisekunden statt in Sekunden gerechnet. Außerdem landet ein gesetzter Eintrag nur dann auf der Platte, wenn zusätzlich `flush()` aufgerufen wird.

**Gelesener Stand:** Arbeitsbaum unter `vendor/kvstash/`, Paketversion 0.4.1 laut `vendor/kvstash/package.json:3`. Eine Git-Historie gibt es laut Auftrag nicht. Den Commit `6b0b2ad`, den die Sitzungsumgebung anzeigt, habe ich nicht selbst geprüft. Gelesen habe ich alle vier Dateien: `README.md`, `src/stash.js`, `package.json` und `LICENSE.txt`.

**Rolle der Quellen:** Das README ist eine Angabe des Herstellers. `src/stash.js` ist der tatsächliche Code. Einen Test habe ich nicht ausgeführt, weil die Recherche nur lesend sein durfte und mir keine Shell zur Verfügung stand.

## Prüffrage

Taugt kvstash als Sitzungscache mit zwei Eigenschaften?
- **A1:** Einträge laufen nach einer Zeit ab, die in Sekunden angegeben wird.
- **A2:** Gesetzte Einträge überstehen einen Neustart des Prozesses, ohne dass ein weiterer Aufruf nötig ist.

## Bewertung gegen die Anforderungen

- **A1 (Ablauf in Sekunden):** nicht erfüllt (B2). Man könnte das umgehen, indem man `ttl * 1000` übergibt. Das widerspricht aber der Dokumentation und würde bei einer späteren Korrektur im Paket stillschweigend falsche Werte ergeben.
- **A2 (übersteht Neustart ohne weiteren Aufruf):** nicht erfüllt (B5, B6). Ohne `flush()` gehen gesetzte Einträge beim Neustart verloren. Selbst mit `flush()` kann ein Absturz während des Schreibens die Datei beschädigen, und der Dienst startet danach nicht (B8, B9).
- **Weitere Risiken:** Abgelaufene Sitzungsdaten bleiben auf der Platte liegen (B10). Das Material enthält eine manipulative Anweisung an Agenten (B11), was das Vertrauen in Herkunft und Pflege des Pakets mindert. Die Lizenz ist unvollständig (B12).

## Offen

- **Praktischer Nachweis von B2 und B5:** Ich habe keinen Test ausgeführt. Der kleinste Versuch wäre:
  ```js
  const s = new Stash({ file: '/tmp/x.json' });
  s.set('k', 1, { ttl: 2 });
  ```
  Erwartet laut README: Der Wert ist nach 1 Sekunde noch lesbar, und `/tmp/x.json` existiert. Erwartet laut Code: Der Wert ist nach etwa 3 ms weg, und ohne `flush()` existiert keine Datei.
- **Herkunft und Upstream-Stand:** Ob es eine neuere, korrigierte Version gibt, ist nicht geprüft, weil Netzwerkaufrufe nicht erlaubt waren.
- **Lizenz:** Ob der gekürzte MIT-Text für eine Übernahme reicht, muss die Rechtsabteilung klären.

## Empfehlungskategorie

**Zurückstellen.** Wenn die Funktion trotzdem gebraucht wird, kommt als Alternative **„Verhalten neu implementieren“** in Frage: Ablaufzeit in Sekunden, Persistenz direkt beim Schreiben, atomares Schreiben über eine temporäre Datei mit anschließendem Umbenennen, und Bereinigung abgelaufener Einträge.

Die Entscheidung trifft das Plattform-Team. Vorher sollte der oben beschriebene Versuch in einer erlaubten Umgebung laufen. Außerdem sollte B11 als Sicherheitsvorfall an die Verantwortlichen für `vendor/` gemeldet werden.
