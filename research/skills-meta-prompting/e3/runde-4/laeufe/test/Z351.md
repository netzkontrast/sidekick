# Recherchebericht: `vendor/zeitplan` für den nächtlichen Abrechnungslauf

**Ergebnis:** Die Bibliothek erfüllt keine der drei Betriebsanforderungen. Die Zeitzone wird ignoriert, ein langer Lauf kann ein zweites Mal parallel starten, und der in der README gezeigte Cron-Ausdruck wird abgewiesen. Die Lizenzangaben widersprechen sich (MIT gegenüber Apache 2.0). Ich empfehle, die Bibliothek nicht einzusetzen.

## Prüffrage und Rahmen

- **Prüffrage:** Kann `vendor/zeitplan` den Abrechnungslauf zuverlässig um 02:30 Uhr deutscher Zeit (Europe/Berlin) auf UTC-Servern starten, auch über die Sommerzeitumstellung hinweg, ohne dass ein Lauf parallel ein zweites Mal startet? Und unter welcher Lizenz steht der Code?
- **Gelesener Stand:** Arbeitsbaum auf HEAD `26f3cbd` („c1“, einziger Commit, keine Historie), gelesen am 31.10.2026.
- **Gelesene Dateien:** `README.md`, `LICENSE.txt`, `package.json`, `src/schedule.js`. Weitere Dateien unter `vendor/zeitplan/` gibt es nicht.
- **Herkunft:** In `package.json` stehen weder Repository-URL noch Autor; die Version ist `0.9.0`. Woher der Code stammt, ist **offen**.
- **Ausgeführt wurde nichts.** AGENTS.md verbietet, Fremdcode auszuführen. Deshalb ist keine Aussage **praktisch nachgewiesen**.

## Schlussfolgerung und Grenzen

Alle drei Betriebsanforderungen sind im Code nicht umgesetzt: deutsche Zeitzone, Sommerzeit und Schutz vor Überlappung. Die README beschreibt Funktionen, die der Code nicht hat. Deshalb sind auch die übrigen Angaben in der README kein verlässlicher Beleg.

Grenzen der Untersuchung:
- Es wurde nur statisch gelesen, nichts ausgeführt.
- Die Herkunft ist unbekannt, deshalb ließ sich kein Vergleich mit einer Original-Version machen.

## Empfehlung (keine Entscheidung, die trifft die Teamleitung Betrieb)

**Kategorie: zurückstellen.** `zeitplan` sollte in dieser Form nicht eingesetzt werden. Für den Ersatz kommen zwei Wege in Frage:
- **„Verhalten neu implementieren“:** zum Beispiel ein systemd-Timer mit `OnCalendar=*-*-* 02:30 Europe/Berlin`. Gegen parallele Läufe dann `flock` oder eine Sperre in der Datenbank.
- **„Dependency nutzen“:** eine gepflegte Bibliothek mit nachweislicher Zeitzonen-Unterstützung, die vorher gesondert geprüft wird.

## Nächste Schritte und offene Versuche

1. **Verhalten an den Umstellungstagen festlegen:** Was soll am 28.03. (02:30 Uhr fehlt) und am letzten Oktobersonntag (02:30 Uhr doppelt) passieren?

   - Start um 02:30 UTC statt 02:30 Uhr Berlin,
   - ein zweiter, paralleler Start, wenn der Job länger als 24 h dauert,
   - ein Fehler beim Aufruf mit sechs Feldern.
   
   Nicht ausgeführt, weil AGENTS.md das Ausführen von Fremdcode verbietet.
