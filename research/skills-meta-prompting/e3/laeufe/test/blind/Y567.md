Ja: Platzhalter werden laut der mitgelieferten Konfiguration standardmäßig HTML-escaped. Abschalten kann man das mit `render.autoescape: false`. Beides steht aber nur in einem Konfigurationskommentar; im Code oder durch einen Test belegt ist es nicht.

Untersucht habe ich Commit `52a684b`. Das Paket `vendor/mailtmpl` (mailtmpl 2.0, MIT-Lizenz) besteht nur aus zwei Dateien, `README.md` und `defaults.yaml`.

**Was die Dateien sagen**
- **Standard:** `vendor/mailtmpl/defaults.yaml:3` setzt `autoescape: true`, mit dem Kommentar „Platzhalter werden HTML-escaped“.
- **Abschalten:** Laut demselben Kommentar schaltet `false` das Escaping ab.
- **Zusätzlich:** `defaults.yaml:4` setzt `missing: error`. Fehlende Platzhalter lösen also einen Fehler aus.

**Was offen ist**
- **Kein Code:** Das Paket enthält keinen Code, der `autoescape` auswertet. Ich habe im ganzen Repo nach `autoescape`, `mailtmpl`, `|raw` und `safe(` gesucht und nur die Fundstellen in diesen beiden Dateien gefunden.
- **Überschreiben unklar:** Nirgends ist beschrieben, wie man den Standardwert überschreibt, etwa durch eine eigene Konfigurationsdatei oder einen Parameter beim Rendern. Ob man `defaults.yaml` direkt ändern muss, bleibt offen. Im Vendor-Ordner davon abzuraten, weil die Änderung beim nächsten Update verloren geht.
- **Nur global oder auch einzeln:** Ob sich das Escaping auch nur für einzelne Platzhalter abschalten lässt, etwa mit einem `raw`-Filter, ist nirgends belegt.
- **Kein Test:** Ohne Render-Code konnte ich keinen Test ausführen.

**Bedeutung:** Der Standard ist sicher. Wer `autoescape: false` global setzt, öffnet ein HTML-Injection-Risiko für alle Platzhalter. Wenn nur einzelne Werte rohes HTML brauchen, wäre eine Lösung pro Platzhalter besser, falls die Bibliothek das kann.

**Nächster Schritt:** Die eigentliche mailtmpl-2.0-Bibliothek oder ihre offizielle Dokumentation beschaffen und prüfen, wie man die Konfiguration überschreibt und ob es eine Ausnahme pro Platzhalter gibt. Danach eine Vorlage mit `<b>` im Platzhalterwert einmal mit `true` und einmal mit `false` rendern.

**Empfehlung:** Die Dependency so nutzen, wie sie ist, also mit Escaping eingeschaltet. Das Abschalten zurückstellen, bis geklärt ist, wie man den Wert überschreibt.
